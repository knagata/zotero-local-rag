# Chromaのネイティブ異常終了後の確認


負の終了コードはOSシグナルによる異常終了として表示する。SIGBUS等ではChromaを開くだけで
再クラッシュする場合があるため、最初の保存はnative clientを開かずwriter lock下でDB一式を
コピーする。保存完了と健康な世代の検証は区別し、検証に失敗したcopyは障害保存として保持する。

HNSWの更新thread数は`CHROMA_HNSW_NUM_THREADS`（既定1）で制御し、native read/write前に
適用する。設定拒否を無視しない。thread数を下げるだけで既存の障害が必ず治るとは保証しない。
復旧copyを使う場合も、全ID・本文・metadataの一致、実検索、再openを確認し、稼働元を保存する。
稼働SQLiteへの直接上書き、vectorの推測、原本欠落や途中取込の記録だけの削除はしない。

Graphのnative読取りはwriter公開と同じ安定inodeのflockをclient closeまで保持する。
writer稼働中・manifest未検証時は保存済みlayout vectorへ戻す。要約の定期状態確認は
SQLiteのID・本文・metadataを照合し、native HNSWを開かない。本文の実検索監査は維持する。

thread制限でも異常終了する場合は、稼働DBを繰り返し更新せず、追加の障害保存を先行する。
`export_persisted_vectors.py`は完成済みraw snapshotから、physical labelの一意性、IDの双方向map、
vectorのdimension/有限性、persisted sequence以後のWAL、SQLite全ID一致を検査して隔離SQLiteへ保存する。
`rebuild_chroma_from_vectors.py`はその完成証明とID/vector hashを検査し、保存vectorを明示して
新しい隔離Chromaだけを作る。原本抽出・モデル実行・manifest変更・自動activationは行わない。
作成完了だけで健康とは扱わず、全ID/本文/metadata/vector、close/reopen、実検索を別途検証する。

`verify_vector_recovery.py`は全ID・本文・metadata・dimensionのSQLite署名を厳密に比較し、
全vectorを入力proofへ照合する。cosine再正規化のfloat32丸めを超える変更は拒否する。
保存vectorの実検索とclose/reopenも検査する。検証開始時に旧証明をverified=falseへ戻し、
全検査が終わるまで健康と公開しない。既存の全DB監査を代替するものではない。
