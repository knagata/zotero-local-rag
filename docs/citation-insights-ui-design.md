# Citation Graph 階層要約・事例ビュー設計

状態: 実装可能（2026-07-19確定）

## 目的

Show Citation Networkで資料を選んだまま、次の情報を迷わず確認できるようにする。

- Zotero概要と資料全体のLLM要約
- 文書順に並んだ節要約
- 原文根拠を持つ構造化事例
- 要約・事例の品質上の問題を報告する導線

この画面は資料一件を深く読むための補助ビューである。複数資料を横断した事例検索、比較、集計、書き出しは今回の対象外とし、必要になった時点で専用ビューを追加する。

## 設計原則

1. **グラフ上の位置と選択を失わせない**
   詳細情報は右サイドバー内で開き、別ページへ移動しない。根拠確認や品質報告をしても選択中のノードとズーム位置を保つ。
2. **概要から根拠へ段階的に詳しくする**
   最初に概要を示し、節要約、事例、原文根拠の順に必要な情報だけを開く。長文を一度に並べない。
3. **品質状態と内容を混同しない**
   `confirmed`、`partial`、`candidate` は明示するが、候補をエラー表示しない。色だけに頼らず、ラベルとアイコンを併用する。
4. **根拠は一操作で確認できるようにする**
   事例カードから画面遷移なしで引用断片を開ける。複数チャンクの根拠は順序を保ってすべて表示する。
5. **欠損値で画面を埋めない**
   地域・時期・集団等が存在しない項目は非表示にする。「不明」の反復や空欄は作らない。
6. **モデル名より研究内容を優先する**
   モデル、生成日時、内部IDなどの来歴は二次情報として控えめに配置する。数値confidenceは通常表示せず、技術詳細でのみ確認可能にする。
7. **誤りの報告は可逆的にする**
   報告時点では要約や事例を消さない。「報告済み・判定待ち」と表示し、メンテナンス時の判定に委ねる。

## 採用する情報構造

既存の右サイドバー最上位タブは維持する。

- `資料一覧`
- `概要/コンテキスト`

Zotero所蔵ノードを選択したときだけ、`概要/コンテキスト` 内に次の内側タブを表示する。

- `概要`
- `節要約 N`
- `事例 N`

この三つを縦一列に連結しない。事例数が多い資料では、概要や節へ戻るためのスクロールが長くなるためである。

外部資料ノードでは既存の概要表示を維持し、内側タブを表示しない。エッジを選択した場合も既存の引用コンテキスト表示に切り替え、内側タブを表示しない。

### ナビゲーション規則

1. Zoteroノードをクリックすると `概要/コンテキスト` が選択され、内側の `概要` が開く。
2. 同じ資料内でタブを切り替えた場合、グラフの選択と表示位置は変えない。
3. 別のノードを選択した場合は、その資料の `概要` に戻る。
4. 事例または節を展開している最中にエッジを選択した場合は、引用コンテキストへ切り替える。
5. ブラウザーの戻る・進む履歴には内側タブや展開状態を積まない。閉じたローカルツール内の一時的な閲覧状態として扱う。
6. 高速にノードを切り替えた場合、古い応答を破棄し、最後に選んだノードの情報だけを表示する。

## 画面構成

### 共通ヘッダー

右サイドバーの本文上部に選択中の資料を固定表示する。

```text
┌──────────────────────────────────────┐
│ 資料タイトル（最大2行）          [↔] │
│ 著者 · 年                            │
│ [概要] [節要約 17] [事例 75]         │
├──────────────────────────────────────┤
│ 選択中タブの内容                     │
└──────────────────────────────────────┘
```

- タイトルは最大2行。超過分は省略し、ホバーとフォーカス時のツールチップで全文を示す。
- 著者・年は1行で省略する。値がなければ行自体を表示しない。
- `[↔]` はサイドバーを推奨幅480pxへ広げる／直前の幅へ戻すボタンである。自動的に幅を変えない。
- ヘッダーと内側タブはサイドバー本文の上端に固定し、内容だけをスクロールする。
- 既存のサイドバー幅340pxを初期値として維持し、最小幅を200pxから280pxへ変更する。最大幅は700pxを維持する。

### 概要タブ

表示順は次のとおり。

1. Zotero概要
2. 資料全体のAI要約
3. 生成・編集操作
4. 来歴と注意書き

AI要約には次の状態を表示する。

| 状態 | 表示 |
|---|---|
| LLM要約あり | 要約本文、生成元、更新日時、`再生成`、`編集`、`問題を報告` |
| 抽出的要約のみ | `抽出的要約`ラベル、本文、`AI要約を生成` |
| 要約なし | 簡潔な説明と`AI要約を生成` |
| 生成中 | 本文領域だけをスケルトン表示し、二重実行を無効化 |
| 生成失敗 | 原因を簡潔に示し、`再試行`を表示。既存要約があれば消さない |

要約下部に「検索と読解を補助する自動生成情報です。重要な判断では原文を確認してください」と常時表示する。警告色ではなく補助テキスト色を使う。

### 節要約タブ

```text
┌──────────────────────────────────────┐
│ [節を検索……                       ] │
│ 17節 · 文書順                        │
│                                      │
│ ▸ 1. Introduction                    │
│   問題設定と対象地域を説明…           │
│                                      │
│ ▾ 2. Field methods                   │
│   調査方法の要約全文……               │
│   生成: Flash · 2026-07-19            │
│   [原文を表示] [問題を報告]           │
└──────────────────────────────────────┘
```

- 節は文書順で表示する。初期状態ではすべて折りたたむ。
- 閉じた行には節名と要約の1行プレビューを表示する。
- 開いた行には全文、控えめな来歴、`原文を表示`、`問題を報告`を表示する。
- 節名と要約本文を対象に絞り込む。200msのdebounce後にローカルAPIへ問い合わせ、入力のたびに全件を描画し直さない。
- 50節を超える場合は最初の50節を描画し、`さらに表示`で50節ずつ追加する。
- 原文は同じカード内に展開し、節を構成するチャンクを文書順に表示する。原文領域は独立スクロールにしない。

### 事例タブ

```text
┌──────────────────────────────────────┐
│ [事例を検索……                     ] │
│ [確定 4 ✓] [部分 36 ◐] [候補 35 ○]  │
│ [節: すべて                 ▾]       │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ ◐ 部分                           │ │
│ │ 地域共同体が沿岸資源の管理規則を…│ │
│ │ [沖縄] [漁業者] [1990年代]        │ │
│ │ 2. Field methods                 │ │
│ │ [根拠を見る] [問題を報告]        │ │
│ └──────────────────────────────────┘ │
│                 [さらに20件を表示]   │
└──────────────────────────────────────┘
```

#### 初期フィルター

- `confirmed` と `partial` を表示する。
- `candidate` は件数を示すが初期状態では非表示にする。
- 状態チップはトグルとして動作し、複数選択できる。最低一つは選択された状態を保つ。
- 事例説明、地域、集団、時期、実践内容を対象に検索する。200msのdebounce後にローカルAPIへ問い合わせ、外部へは送信しない。
- 節フィルターを一つ選択できる。

候補を初期非表示にする理由は、探索範囲を失わずに通常閲覧のノイズを抑えるためである。候補は削除・隔離されたものではない。

#### 事例カード

- 状態をカード左上にテキストと記号で表示する。
- 説明は閉じた状態で最大3行、カードを開くと全文を表示する。
- 地域、集団、時期、実践等は値があるものだけをチップ表示する。
- 通常画面では数値confidenceを表示しない。展開時の`技術詳細`で、case ID、confidence、生成元、更新日時を確認できる。
- `根拠を見る`で根拠をインライン展開する。
- 最初の20件を表示し、`さらに20件を表示`で追加する。ページ番号による遷移は使わない。
- 無効化済みの事例は件数にも一覧にも含めない。

#### 原文根拠

```text
根拠 1 / 2 · chunk 031
「原文から保存された引用断片……」

根拠 2 / 2 · chunk 032
「次のチャンクへ続く引用断片……」
```

- `case_evidence` の順序を維持する。
- フィールド別根拠がある場合は、`説明`、`地域`等のラベルを付ける。
- 引用は原文と視覚的に区別し、改変せず表示する。
- 根拠が欠損している異常データでは事例を通常表示せず、「根拠データを読み込めません」と再試行・報告導線を表示する。

## 品質報告

節要約と事例の`問題を報告`は共通モーダルを使う。

### 事例の理由

- 事例ではない
- 原文にない内容を含む
- フィールドの根拠が不十分
- 文脈または対象の取り違え
- 重複事例
- その他

### 要約の理由

- 原文にない内容を含む
- 重要な限定条件が失われている
- 対象または因果関係の取り違え
- 意味が通らない
- その他

詳細欄は10文字以上を必須とし、事例では関連する根拠チャンクを初期選択する。送信後も対象を消さず、カードに`報告済み・判定待ち`を表示する。同じ内容の二重送信は無効化する。

モーダルの文言は、報告が即時削除ではなくメンテナンス時の確認対象になることを明示する。送信成功はトーストとカード内表示の両方で伝える。

## 状態設計

| 状態 | 表示と動作 |
|---|---|
| 読み込み中 | 対象タブ内だけに3行のスケルトン。グラフ操作は止めない |
| 未処理 | 「まだ生成されていません」とメンテナンス実行方法を表示 |
| 処理済み・0件 | 「この資料から該当する事例は抽出されませんでした」と表示 |
| フィルター結果0件 | 選択中フィルターを示し、`条件を解除`を表示 |
| 一部取得失敗 | 取得済み内容を保ち、失敗箇所だけに`再試行` |
| 全体取得失敗 | エラー概要、`再試行`、ログ参照先を表示 |
| 古い応答 | 表示せず破棄する |
| 報告済み | 内容を維持し、`報告済み・判定待ち`を表示 |

`未処理`と`処理済み・0件`を区別するため、バックエンドは抽出実行状態を返す。行が0件という事実だけから状態を推測しない。

## 視覚仕様

既存のダークテーマを維持し、新規UIは次のセマンティックトークンを追加して使用する。

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--radius-sm: 4px;
--radius-md: 6px;
--control-height: 32px;
--focus-ring: var(--node-zotero);
--status-confirmed: #76d19a;
--status-partial: #e6b35a;
--status-candidate: #b8b2c0;
--status-reported: #8eb1f0;
```

- 本文: 13px / 1.55
- 補助情報: 11px / 1.4
- セクション見出し: 13px / 1.3、600 weight
- タブ・ボタン: 12px / 1、600 weight
- カード余白: 12px
- カード間隔: 8px
- 境界線: 1px `--outline-variant`
- キーボードフォーカス: 2px `--focus-ring`、2px offset
- 通常本文と背景のコントラスト比: 4.5:1以上
- UI境界・フォーカス・状態記号のコントラスト比: 3:1以上

状態バッジは各状態色を文字色に使い、背景を同色16%と`--surface`の混色、境界を同色45%と`--surface`の混色にする。色が見えなくてもラベルと記号で判別できるようにする。赤は読み込み失敗等の操作上のエラーに限定し、`candidate`には使わない。

## 幅とレスポンシブ動作

この画面はデスクトップを対象とする。

| サイドバー幅 | 動作 |
|---|---|
| 420–700px | 全ラベル、横並び操作、カードメタデータを表示 |
| 280–419px | 操作を折り返し、補助メタデータを次行へ移動 |
| 280px未満 | サポートしない。リサイズ下限を280pxにする |

横スクロールは発生させない。チップは折り返し、長いDOI・IDは任意位置で改行する。ポインターが粗い環境では操作対象の最小高を44pxに上げる。

## キーボードとアクセシビリティ

- 内側タブは `tablist`、`tab`、`tabpanel` を使う。
- 左右矢印で隣のタブ、Home/Endで先頭・末尾へ移動する。
- 折りたたみ見出しはbutton要素とし、`aria-expanded` と `aria-controls` を更新する。
- 状態チップは押下状態を `aria-pressed` で伝える。
- 読み込み結果と報告完了は控えめな `aria-live="polite"` で通知する。
- モーダルはフォーカスを内部に閉じ込め、Escapeで閉じ、閉じた後は起点ボタンへ戻す。
- アイコンだけのボタンには可視ツールチップと `aria-label` を付ける。
- `prefers-reduced-motion` では展開アニメーションを無効化する。通常時も120–160msに収める。
- 画面拡大200%でも情報と操作を失わない。

## APIと実装境界

ノード選択時に長い節・事例データを一括取得しない。次のローカルAPIに分ける。

### `GET /api/node/insights?key={item_key}`

最初の概要表示とタブ件数に必要な軽量データを返す。

```json
{
  "item_key": "265KQMRZ",
  "abstract": "...",
  "summary": {"text": "...", "kind": "llm", "model": "...", "updated_at": "..."},
  "sections": {"status": "available", "count": 17},
  "cases": {
    "status": "available",
    "counts": {"confirmed": 4, "partial": 36, "candidate": 35}
  }
}
```

`status` は `not_processed`、`processed_empty`、`available` のいずれかとする。

### `GET /api/node/sections`

引数: `key`、`q`、`cursor`、`limit`。既定limitは50。文書順の節ID、見出し、要約、来歴、報告状態を返す。節原文は含めない。`q`変更時はcursorを破棄する。

### `GET /api/node/section-source`

引数: `key`、`section_id`。節を構成するチャンクを文書順で返す。`原文を表示`時だけ呼ぶ。

### `GET /api/node/cases`

引数: `key`、`q`、`statuses`、`section_id`、`cursor`、`limit`。既定limitは20。無効化済み事例を除外し、カード表示データと根拠件数を返す。根拠本文は含めない。検索・フィルター変更時はcursorを破棄する。

### `GET /api/case/evidence`

引数: `case_id`。順序付き根拠、チャンクID、フィールド名を返す。`根拠を見る`時だけ呼ぶ。

### `POST /api/quality-report`

要約・事例に共通の入口を設ける。対象種別、安定ID、理由、詳細、関連チャンクIDを受け取り、既存の品質報告ストレージへ保存する。CSRF相当の防御としてJSON以外を拒否し、サーバーは引き続き`127.0.0.1`だけで待ち受ける。

### 実装分離

- SQLiteの取得とレスポンス整形は新規のデータサービスへ分離し、単体テスト可能にする。
- `scripts/show_citation_graph.py` のFastAPIルートは入力検証とサービス呼び出しだけにする。
- フロントエンドは現行HTML生成方式を維持するが、状態と操作を `InsightsPane` 名前空間へまとめる。
- 既存の `_ctxPaneReq` と同等の要求世代番号を全API呼び出しで共有し、古い応答を破棄する。
- DBの表示用問い合わせはベクトル検索や外部APIを呼ばず、SQLiteだけで完結させる。

## 性能基準

- ローカル環境で、ノード選択から概要枠表示まで150msを目標とする。
- 節・事例タブは初回選択時に遅延取得し、同じ資料内ではメモリーキャッシュする。
- 事例は20件、節は50件ずつDOMへ追加する。
- 一つのタブに同時保持するカードは原則100件以下とし、超過時は古い非表示ページをDOMから外す。
- 根拠は展開時だけ取得し、閉じても同一セッション中は再利用する。
- ノード変更時に未完了要求を中断できる場合は中断し、できない場合も要求世代番号で結果を破棄する。

## セキュリティとプライバシー

- DB由来のタイトル、要約、原文、事例はHTML文字列として連結せず、原則 `textContent` で描画する。
- Markdownを許可する箇所は設けない。将来許可する場合もサニタイズを必須とする。
- 閲覧とフィルターでは外部APIへ送信しない。
- AI要約の生成・再生成だけは既存のLLM送信ポリシーと`no-cloud`判定に従う。
- 品質報告はローカルDBへ保存し、外部へ自動送信しない。

## 受入基準

### 機能

- Zoteroノードでは概要・節要約・事例の件数と内容を表示できる。
- 外部ノードとエッジでは既存表示が変わらない。
- 75件以上の事例を持つ資料でも最初はconfirmed/partialだけを20件表示する。
- candidateを明示操作で表示できる。
- 複数チャンク根拠を保存順に表示できる。
- 無効化済み事例を件数・一覧・検索に含めない。
- 未処理と処理済み0件を異なる文言で表示できる。
- 品質報告後も内容が残り、判定待ち状態が表示される。

### 操作と表示

- 280px幅で横スクロールが発生しない。
- 高速に複数ノードを選択しても最後のノード以外の情報が混入しない。
- 読み込み失敗後に、グラフを再起動せず対象箇所だけ再試行できる。
- マウスなしでタブ切替、カード展開、根拠確認、報告ができる。
- 現行ダークテーマ、200%拡大、reduced motionで利用できる。
- 状態を色だけで区別していない。

### 回帰

- 既存の資料一覧検索、コレクション絞り込み、ノード選択、エッジ選択、概要取得、AI要約編集が動作する。
- サイドバーの開閉・横リサイズ・縦リサイズが動作する。
- ブラウザーを閉じてもローカルサーバーの終了方法は変わらない。

## テスト方針

- データサービス: 状態別件数、無効化除外、ページング、根拠順、未処理/0件判定を単体テストする。
- API: 正常、未知のitem key、不正status、limit上限、報告の入力検証をテストする。
- UIロジック: 古い要求の破棄、フィルター、追加読み込み、報告済み状態をテストする。
- ブラウザー: キーボード操作、フォーカス復帰、280px幅、ダークテーマを確認する。
- 実データ確認: `265KQMRZ` の17節・75事例と複数チャンク根拠1件を基準ケースに使う。

## 実装順序

1. 表示用データサービスとAPI、抽出実行状態の永続化を追加する。
2. 共通ヘッダーと内側タブ、概要タブを既存表示へ接続する。
3. 節要約タブと節原文の遅延表示を追加する。

## 今回採用しない案

- **独立した新規ビューを先に作る**: 一資料を読みながら根拠を確認する用途では、グラフとの往復と選択状態の再現が負担になる。
- **事例をグラフノードとして表示する**: ノード数とエッジ数が急増し、引用関係の視認性を損なう。
- **概要・節・事例を一つの長い画面に並べる**: 情報量の多い資料で目的の情報へ戻りにくい。
- **candidateを最初から全表示する**: 回収率は変えずに、通常閲覧時の認知負荷だけが増える。
- **カードに数値confidenceを常時表示する**: 精密さを過度に印象づけ、内容と根拠より内部スコアへ注意を向ける。

横断検索の必要性が生じた場合は、同じデータサービスとカード部品を使い、別画面として「事例エクスプローラー」を追加する。その時点で複数資料、地域、時期、状態、全文検索、比較・書き出しを設計する。
